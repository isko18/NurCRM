# Превью уроков базы знаний — API для фронта

Поле `thumbnail` реализовано на бэкенде: приходит в GET, принимается и в JSON, и в multipart,
переживает PATCH без файла. Контракт совпадает с тем, что фронт уже отправляет — менять
`knowledgeBase.js` не нужно.

**Базовый URL:** `/api/main/public/knowledge-base/` (эндпоинты и их URL не менялись)

> ⚠️ **Нужен деплой с миграцией.** До `python manage.py makemigrations main && python manage.py migrate`
> на сервере колонок в базе нет и эндпоинт упадёт. После деплоя проверьте `OPTIONS` — `thumbnail`
> должен появиться в схеме.

Реализация: [`models.py`](models.py) (модель), [`serializers.py`](serializers.py) (поле и
replace-стратегия), [`bracket_parser.py`](bracket_parser.py) (multipart), [`views.py`](views.py) (парсеры).

---

## 1. Чтение

В каждом уроке появилось поле `thumbnail`. Это **всегда строка** — `null` не приходит никогда.

```jsonc
{
  "id": "079f1579-ac00-4400-a593-8fe402fa35b5",
  "title": "Маркет",
  "lessons": [
    {
      "id": "fb66a248-0d6b-4b31-bfee-ead07d856c0e",
      "title": "Интерфейс кассира",
      "description": "работа с интерфейсом кассира",
      "url": "https://youtu.be/ikRpCGdyisU",
      "thumbnail": "https://app.nurcrm.kg/media/knowledge-base/thumbnails/2026/08/preview.jpg",
      "order": 0,
      "created_at": "2026-08-29T18:18:48.052516+06:00"
    },
    {
      "title": "Настройки",
      "thumbnail": "",          // пусто → фронт строит превью из YouTube/Vimeo
      "…": "…"
    }
  ],
  "created_at": "2026-08-29T18:13:45.150606+06:00",
  "updated_at": "2026-08-29T18:18:48.053206+06:00"
}
```

| Значение | Что это | Что делает фронт |
|---|---|---|
| `"https://app.nurcrm.kg/media/…"` | Админ загрузил файл | Показывает как есть — URL уже абсолютный |
| `"https://cdn.example.com/p.jpg"` | Админ указал ссылку | Показывает как есть |
| `""` | Кастомного превью нет | Fallback на YouTube / Vimeo из `lesson.url` |

Файловые превью отдаются абсолютным URL — `resolveMediaUrl` на них сработает вхолостую и ничего
не сломает. Порядок уроков в `lessons` уже отсортирован по `order`.

## 2. Запись

Одно поле `thumbnail` принимает четыре разных вещи. Разница между «пусто» и «не прислали» —
принципиальная.

| Что отправили | Что произойдёт |
|---|---|
| `<File>` | Файл сохраняется, ранее указанная ссылка очищается |
| `"https://…"` | Ссылка сохраняется, ранее загруженный файл удаляется со storage |
| `""` или `null` | **Явная очистка:** файл удаляется, ссылка обнуляется. Урок вернётся к YouTube-превью |
| поле не отправлено | **Старое превью сохраняется.** Именно так редактируют урок, не трогая картинку |

> ⚠️ **Не отправляйте `thumbnail: ""` «на всякий случай».** Пустая строка — это команда «удалить
> превью», а не «оставить как было». Если пользователь не трогал картинку, ключа в теле быть не должно.

### Ограничения файла

| Правило | Значение |
|---|---|
| Форматы | `image/jpeg`, `image/png`, `image/webp`, `image/gif` |
| Максимальный размер | 5 МБ |
| Проверка содержимого | Файл открывается как изображение — переименованный `.pdf` не пройдёт |
| Длина ссылки | до 500 символов |

Валидацию размера и MIME стоит продублировать на клиенте — так пользователь узнает о проблеме
до пятимегабайтной загрузки.

## 3. JSON

Когда файлов нет — обычный `application/json`, как и раньше.

### POST — создание курса

```jsonc
{
  "title": "Маркет",
  "lessons": [
    {
      "title": "Интерфейс кассира",
      "description": "работа с интерфейсом кассира",
      "url": "https://youtu.be/ikRpCGdyisU",
      "thumbnail": "https://cdn.example.com/custom-preview.jpg"
    },
    {
      "title": "Настройки",
      "url": "https://youtu.be/zuKxCEnehx0"
      // thumbnail не указан — превью не будет, сработает YouTube-fallback
    }
  ]
}
```

### PATCH — только название

```json
{ "title": "Новое название курса" }
```

Уроки при таком PATCH не трогаются — ни порядок, ни превью.

---

## 4. Multipart

Bracket-notation поддержана на бэкенде — тот формат, который `knowledgeBase.js` уже собирает.
Менять на JSON-строку или на плоские `lessons_0_thumbnail` не нужно.

```
title                    = "Маркет"
lessons[0][title]        = "Интерфейс кассира"
lessons[0][description]  = "работа с интерфейсом"
lessons[0][url]          = "https://youtu.be/ikRpCGdyisU"
lessons[0][thumbnail]    = <File>              // файл

lessons[1][title]        = "Настройки"
lessons[1][url]          = "https://youtu.be/zuKxCEnehx0"
lessons[1][thumbnail]    = "https://cdn.example.com/p.jpg"   // или строка-ссылка

lessons[2][title]        = "Отчёты"
lessons[2][url]          = "https://youtu.be/abc"
                           // thumbnail не отправлен — старое превью сохранится
```

Индексы сортируются численно, поэтому `lessons[10]` встанет после `lessons[9]`, а не между `[1]`
и `[2]`. Пропуски в нумерации допустимы — важен только относительный порядок.

`order` присваивается по позиции в массиве и начинается с нуля. Отправлять его не нужно,
он read-only.

## 5. Замена списка уроков

PATCH или PUT с полем `lessons` по-прежнему заменяет весь список. Но реализация теперь не удаляет
уроки вслепую, иначе загруженные превью терялись бы при каждом сохранении.

```
урок из тела запроса
    │
    ├─ прислан id и такой урок есть ──────────► обновляем его на месте
    │
    ├─ id нет, но url совпал с существующим ──► обновляем его на месте
    │
    └─ ничего не совпало ─────────────────────► создаём новый урок

уроки, которых не оказалось в теле ───────────► удаляются вместе с файлами превью
```

> **Присылайте `id` при редактировании** — теперь поле принимается. Тогда переименование урока или
> смена ссылки на видео не потеряет превью. Без `id` спасает совпадение по `url`, но если админ
> поменял и название, и ссылку — урок будет считаться новым, а превью придётся загрузить заново.

Курс должен содержать минимум один урок: `lessons: []` вернёт `400` «Добавьте хотя бы один урок».
Чтобы удалить все уроки, удаляйте курс.

## 6. Ошибки

Ошибки уроков приходят массивом, выровненным по индексу: у валидных уроков — пустой объект.
Это позволяет показать ошибку рядом с нужным полем в форме.

```jsonc
{
  "lessons": [
    {},                                                  // урок 1 — ок
    { "thumbnail": ["Файл превью больше 5 МБ."] },        // урок 2
    { "url": ["Введите правильный URL."] }               // урок 3
  ]
}
```

| Текст | Причина |
|---|---|
| Файл превью больше 5 МБ. | Размер файла превышен |
| Допустимые форматы превью: JPEG, PNG, WebP, GIF. | Неподходящий MIME-тип |
| Загрузите корректное изображение… | Файл не открывается как картинка |
| Передайте файл изображения или ссылку на него. | В `thumbnail` пришла строка, не похожая на URL |
| Ссылка на превью длиннее 500 символов. | Слишком длинный URL |
| Добавьте хотя бы один урок. | Пустой массив `lessons` |
| Курс с таким названием уже есть. | Название курса не уникально |

Ошибки уровня курса (`title`, `lessons`) приходят на верхнем уровне тела, как и раньше.

## 7. Что не сделано

### Авторизация осталась открытой

`POST`, `PATCH` и `PUT` по-прежнему доступны без токена. Закрыть их односторонне значило бы
сломать админку прямо сейчас: она ходит без Bearer.

Это скоординированное изменение. Порядок такой: сначала `knowledgeBase.js` начинает слать токен,
затем бэкенд включает `IsAdminUser` на write-методы.

### Хранилище файлов

Превью пишутся в локальный `media/` на сервере (`MEDIA_ROOT = BASE_DIR / 'media'`). Если этот
каталог лежит внутри релизной директории, файлы не переживут следующий деплой — тогда картинки
исчезнут, а превью молча вернутся к YouTube-fallback. Проверяется на стороне инфраструктуры,
до того как админы начнут массово грузить картинки.

## 8. Проверка после деплоя

1. `GET` списка курсов — в каждом уроке есть ключ `thumbnail`, у уроков без превью это `""`.
2. Загрузка файла в админке: после сохранения `thumbnail` — абсолютный URL, картинка открывается
   по прямой ссылке.
3. Указание ссылки вместо файла: `thumbnail` вернулся ровно той строкой, что отправили.
4. Редактирование урока без выбора нового файла — превью на месте.
5. Очистка превью через `thumbnail: ""` — карточка вернулась к YouTube-превью.
6. PATCH только с `title` — уроки и превью не пострадали.
7. Перестановка уроков местами — `order` пересчитался, превью остались у своих уроков.
8. Файл 6 МБ — `400` с текстом про 5 МБ, форма показывает ошибку у нужного урока.
9. Переименованный `.pdf` с расширением `.jpg` — `400`, а не битая картинка на карточке.
10. `OPTIONS` на эндпоинт — `thumbnail` присутствует в схеме `POST`.

```bash
# поле есть в ответе
curl -s "https://app.nurcrm.kg/api/main/public/knowledge-base/" \
  | jq '.results[0].lessons[0].thumbnail'

# поле есть в схеме
curl -s -X OPTIONS "https://app.nurcrm.kg/api/main/public/knowledge-base/" \
  | jq '.actions.POST.lessons.child.children.thumbnail'

# создание со ссылкой-превью
curl -s -X POST "https://app.nurcrm.kg/api/main/public/knowledge-base/" \
  -H "Content-Type: application/json" \
  -d '{"title":"Тест","lessons":[{"title":"Урок 1","url":"https://youtu.be/dQw4w9WgXcQ","thumbnail":"https://cdn.example.com/p.jpg"}]}'

# загрузка файла (multipart, bracket notation)
curl -s -X POST "https://app.nurcrm.kg/api/main/public/knowledge-base/" \
  -F 'title=Тест 2' \
  -F 'lessons[0][title]=Урок 1' \
  -F 'lessons[0][url]=https://youtu.be/dQw4w9WgXcQ' \
  -F 'lessons[0][description]=' \
  -F 'lessons[0][thumbnail]=@/path/to/preview.jpg'
```
