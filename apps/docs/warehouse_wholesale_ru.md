# Warehouse: оптовая цена и опт/розница для агентов (для фронта)

Документ описывает новые поля и поведение API после добавления:
1. **второй цены** у товара (оптовая) — `wholesale_price`;
2. **переключателя опт/розница** на документе продажи — `is_wholesale`;
3. **права агента продавать оптом** — `can_sell_wholesale` (выдаёт владелец).

Базовый префикс всех путей: `/api/warehouse/`.

---

## 1. Товар: розничная и оптовая цена

У товара (`WarehouseProduct`) теперь **две цены продажи**:

| Поле | Назначение |
|---|---|
| `price` | Розничная цена продажи за учётную единицу (считается из закупки и наценки, если наценка > 0). |
| `wholesale_price` | **Новое.** Оптовая цена продажи за ту же единицу. Заполняется **вручную**, из наценки не считается. |

Оба поля присутствуют в карточке товара на чтение и запись.

### Где редактировать
- Создание товара: `POST /api/warehouse/{warehouse_uuid}/products/`
- Обновление: `PATCH /api/warehouse/products/{product_uuid}/`

```jsonc
// PATCH /api/warehouse/products/{product_uuid}/
{
  "price": 100.00,            // розница
  "wholesale_price": 85.00    // опт
}
```

Если `wholesale_price` не задана (0 или не передана) — при оптовой продаже система откатится на розничную `price` (см. ниже).

---

## 2. Документ продажи: переключатель опт/розница

У документа (`Document`, тип `SALE`) добавлено поле:

| Поле | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `is_wholesale` | bool | `false` | Переключатель опт/розница. Влияет только на документы `SALE`. |

### Как работает авто-подстановка цены строки
Для **строки документа без явной цены** (`price` не передан или `null`) бэкенд сам подставляет цену с карточки товара:

```
is_wholesale = true  → wholesale_price (если > 0), иначе price (розница)
is_wholesale = false → price (розница)
```

> Если фронт передаёт `price` в строке явно — он используется как есть, переключатель его **не** перебивает. Чтобы сработала авто-подстановка опта/розницы — **не присылайте `price` в строке**.

### Создание продажи
`POST /api/warehouse/documents/sale/`

```jsonc
{
  "is_wholesale": true,             // опт
  "counterparty": "<uuid>",
  "warehouse_from": "<uuid>",       // для опт-продажи владельца можно опустить — подставится из первой строки
  "payment_kind": "cash",           // cash | credit
  "items": [
    { "product": "<uuid>", "qty": 10 }        // price не передаём → возьмётся wholesale_price
    // { "product": "<uuid>", "qty": 5, "price": 90 }  // явная цена — используется как есть
  ]
}
```

### Что приходит в ответе по строкам
В каждой строке документа (`items[]`) теперь отдаются цены товара для удобства отображения:

| Поле строки | Описание |
|---|---|
| `price` | Итоговая цена строки (что реально применилось). |
| `product_price` | Розничная цена товара (read-only). |
| `product_wholesale_price` | Оптовая цена товара (read-only). |
| `product_discount_percent` | Скидка с карточки товара, %. |

Поле документа `is_wholesale` также возвращается в ответе и в списке документов.

## 3. Право агента продавать оптом (`can_sell_wholesale`)

По умолчанию **агент продаёт только в розницу**. Опт включается владельцем индивидуально для каждого агента.

### 3.1. Поле на агенте
В объекте агента (`CompanyWarehouseAgent`) добавлено:

| Поле | Тип | По умолчанию | Кто меняет |
|---|---|---|---|
| `can_sell_wholesale` | bool | `false` | Только владелец/админ |

Возвращается (read-only) в сериализаторе агента — фронт может показать текущее состояние тумблера.

### 3.2. Владелец выдаёт/снимает право
Два owner-only эндпоинта (доступ только владельцу/админу):

**A. Обновление настроек уже активного агента**
`PATCH /api/warehouse/agents/company-requests/{id}/common-access/`
```jsonc
{ "can_sell_wholesale": true }
```

**B. Прямое назначение агента (или обновление) — можно сразу с правом**
`POST /api/warehouse/agents/company-memberships/`
```jsonc
{
  "user": "<uuid>",
  "can_sell_wholesale": true,
  "assigned_warehouse": "<uuid>"   // опционально
}
```

Оба эндпоинта в ответе возвращают полный объект агента (с актуальным `can_sell_wholesale`).

### 3.3. Поведение при продаже агентом

| Условие | Результат |
|---|---|
| Агент создаёт продажу без `is_wholesale` (или `false`) | Розница (по умолчанию). |
| Агент с `can_sell_wholesale=true` шлёт `is_wholesale=true` | Опт разрешён, цены берутся оптовые. |
| Агент с `can_sell_wholesale=false` шлёт `is_wholesale=true` | **Ошибка `400`** (см. ниже). |
| Владелец/админ создаёт продажу | Опт всегда доступен, без ограничений. |

Гейт работает на всех путях продажи агента:
- `POST /api/warehouse/agent/documents/` (документы агента)
- `POST /api/warehouse/documents/sale/` (когда вызывает агент)
- `POST /api/warehouse/agent-carts/{id}/create-sale/` (создание продажи из заявки агента; здесь `is_wholesale` принимается в теле запроса)

### Пример ошибки `400`
```jsonc
{
  "is_wholesale": "У агента нет доступа к оптовым продажам. Обратитесь к владельцу."
}
```

## 4. Памятка для фронта

- **Тумблер «Опт / Розница»** на экране продажи → поле `is_wholesale` документа.
- Чтобы тумблер реально менял цены — **не отправляйте `price` в строках** (пусть бэкенд подставит опт/розницу). Если нужна ручная цена — присылайте `price`, тогда тумблер на неё не влияет.
- **Доступность тумблера для агента**: показывать/разрешать опт только если у агента `can_sell_wholesale=true`. Иначе при `is_wholesale=true` придёт `400`.
- **Экран товара**: добавить поле «Оптовая цена» → `wholesale_price` (рядом с «Цена продажи» `price`).
- **Экран управления агентами (у владельца)**: добавить тумблер «Разрешить оптовые продажи» → `can_sell_wholesale`, сохранять через `common-access` или `company-memberships`.
