## 1. Общий обзор и архитектура

В **NurCRM** реализована гибридная система работы с весовым оборудованием, закрывающая любые потребности розничных магазинов, супермаркетов и складских помещений:

```
┌────────────────────────────────────────────────────────────────────────┐
│                               NurCRM                                   │
│  - Учёт товаров по весу (is_weight = True, единица: кг)                │
│  - Управление PLU-номерами (автогенерация под блокировкой БД)         │
│  - Настройки компании (режим ШК, раскладка, единица суммы)            │
└──────────────────┬─────────────────────────────────┬───────────────────┘
                   │                                 │
     (Вариант А: Офлайн-экспорт)         (Вариант Б: Онлайн-агент)
                   │                                 │
                   ▼                                 ▼
       Файл .TXP / .XLS                     WebSocket / REST API
                   │                                 │
                   ▼                                 ▼
        ПО весов (RTPLU Manager)             Локальный Scale Agent
                   │                                 │
                   └────────────────┬────────────────┘
                                    │
                                    ▼
                         Электронные весы с печатью
                         (Rongta RLS, CAS, Штрих и др.)
                                    │
                         Печать термоэтикетки EAN-13
                                    │
                                    ▼
                         Сканер штрихкода на кассе (POS)
                                    │
                                    ▼
       Касса POS (`/api/main/pos/sales/<cart_id>/scan/`)
       - Распознавание PLU
       - Автоматический расчёт веса / суммы
       - Добавление товара в чек с количеством в кг
```

### Поддерживаемые типы оборудования
- **Системные весы с печатью этикеток:** Rongta RLS1000 / RLS1100, CAS CL-3000 / CL-5000 / CL-7000, Штрих-Принт, Масса-К.
- **Интерфейсы связи:** TCP/IP (Ethernet/Wi-Fi), USB, RS-232 (COM-порт).

## 2. Модели данных и структура базы данных

### Product (Весовые товары и PLU)
Код: `apps/main/models.py`

| Поле | Тип | Описание |
|---|---|---|
| `is_weight` | `BooleanField(default=False)` | Признак весового товара. Если `True`, товар продаётся по весу (в килограммах). |
| `unit` | `CharField(max_length=32, default="шт.")` | Единица измерения. Для весовых товаров обычно `кг` или `kg`. |
| `plu` | `PositiveIntegerField(null=True, blank=True)` | Номер PLU (Price Look-Up) — уникальный числовой идентификатор товара на весах (1..99999). Привязывается к горячим клавишам и зашивается в штрихкод. |
| `quantity` | `DecimalField(max_digits=12, decimal_places=3)` | Остаток товара с точностью до 3 знаков после запятой (грамм). |
| `price` | `DecimalField(max_digits=12, decimal_places=2)` | Розничная цена за 1 единицу (за 1 кг весового товара). |
| `code` | `CharField(max_length=64)` | Внутренний код/артикул товара. |

#### Генерация PLU под блокировкой БД
Для предотвращения дублирования PLU при одновременном добавлении или экспорте товаров в компании используется блокировка PostgreSQL Advisory Lock:
```python
key = int(str(company_id).replace("-", "")[:16], 16) & 0x7FFFFFFFFFFFFFFF
cur.execute("SELECT pg_advisory_xact_lock(%s::bigint);", [key])
```
Если весовому товару ещё не присвоен `plu`, система вычисляет `max(plu) + 1` в рамках компании и сохраняет его.

### Company (Настройки штрихкодов весов)
Код: `apps/users/models.py`

Каждая компания хранит конфигурацию разбора штрихкодов весов:

| Поле | Тип / Значения | Дефолт | Описание |
|---|---|---|---|
| `scale_barcode_mode` | `auto`, `weight`, `amount` | `auto` | Что зашито в поле данных штрихкода: вес или сумма. `auto` — определяется по префиксу (20 = вес, 25 = сумма). |
| `scale_barcode_layout` | `plu`, `code` | `plu` | Раскладка полей EAN-13. `plu` — 5 знаков PLU + 5 знаков значения. `code` — 6 знаков PLU + 4 знака значения. |
| `scale_barcode_amount_unit` | `tiyin`, `som` | `tiyin` | Единица измерения, если штрихкод содержит сумму: `tiyin` (в тыйынах / копейках, делится на 100) или `som` (в целых сомах). |
| `scale_api_token` | `CharField(max_length=128)` | UUID | Постоянный токен авторизации для локального весового агента. |

## 3. Режим 1: Офлайн-интеграция (Экспорт каталога в весы)

### Принцип работы (Офлайн)
1. Менеджер или товаровед нажимает кнопку **«Экспорт для весов»** в веб-интерфейсе NurCRM.
2. Сервер формирует готовый файл с товарами компании, у которых `is_weight = True`.
3. Файл скачивается на компьютер оператора.
4. В официальной программе управления весами (например, **Rongta PLU Management Software / RTPLU.exe**):
   - Выполняется импорт скачанного файла.
   - Нажимается кнопка отправки данных в весы по IP-адресу весов (по сети).
5. Весы готовы к автономной работе без постоянного подключения к интернету.

---

### Эндпоинт экспорта
`GET /api/main/products/scale-export/`

**Заголовки запроса:**
```http
GET /api/main/products/scale-export/ HTTP/1.1
Host: api.nurcrm.kg
Authorization: Bearer <access_token>
```

**Query-параметры:**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `format` | string | `txp` | Формат выгрузки: `txp` (нативный формат Rongta RLS, рекомендуется) или `xls` (Excel). |
| `product_ids` | string | — | Список UUID товаров через запятую (если нужно выгрузить только определенные позиции). |
| `barcode_type` | int | `5` | Номер шаблона штрихкода на весах. |
| `department` | int | `21` | Номер отдела (участвует в префиксе штрихкода, например префикс 21). |
| `shelf_life_days`| int | `15` | Срок годности товара по умолчанию (в днях). |
| `unit_code` | int | `4` | Код единицы измерения весов (`4` = kg) — для формата `txp`. |
| `translit` | int | `1` | `1` — транслитерировать названия в латиницу; `0` — оставить как есть. |
| `assign_plu` | int | `1` | `1` — автоматически присвоить PLU товарам, у которых он не задан; `0` — не менять. |

**Заголовки ответа:**
- `Content-Type`: `application/octet-stream` (для TXP) или `application/vnd.ms-excel` (для XLS).
- `Content-Disposition`: `attachment; filename="scale_weight_products.TXP"`
- `X-Scale-Products-Count`: количество выгруженных товаров.

---

### Форматы файлов (.TXP и .xls)

#### Формат `.TXP` (Основной рабочий формат Rongta)
- **Кодировка:** `UTF-16 LE` с сигнатурой BOM (`\xff\xfe`).
- **Разделитель колонок:** Символ табуляции (`\t`).
- **Разделитель строк:** `\r\n` (CRLF).
- **Цена:** Формат `X,XXX` (3 знака после запятой, десятичный разделитель — **запятая**, например `160,000`).
- **Структура заголовка (24 колонки):**
  `Горячая клавиша`, `Название`, `LF код`, `Код`, `Тип штрихкода`, `Цена единицы`, `Вес единицы`, `Количество единиц`, `Отдел`, `Вес PT`, `Срок годности`, `Тип упаковки`, `Тара`, `Ошибка(%)`, `Сообщение 1`, `Сообщение 2`, `Этикетка`, `Таблица скидок`, `Учётная запись`, `sPluFieldTitle20`, `Учётная запись`, `Recommend days`, `nutrition`, `Ice(%)`.
- **Строки данных (23 поля):** В поля `LF код` и `Код` подставляется `Product.plu`.

#### Формат `.xls` (Резервный формат Excel 97-2003)
Генерируется библиотекой `xlwt`. Содержит 18 стандартных колонок таблицы PLU-менеджера.

---

### Транслитерация и ограничения Rongta RLS

> [!WARNING] Ограничения встроенного ПО весов Rongta RLS
> 1. **Длина названия товара:** Максимум **36 символов** (`SCALE_NAME_MAX = 36`). Если строка длиннее, буфер весов переполняется, и официальная программа `RTPLU.exe` падает с ошибкой `Access violation`. Бэкенд NurCRM автоматически обрезает названия до 36 символов.
> 2. **Кодировка дисплея и этикетки:** Большинство прошивок весов Rongta не поддерживают русский алфавит (кириллицу), превращая русские буквы в знаки вопроса `??????`. Параметр `translit=1` (включен по умолчанию) автоматически транслитерирует названия (`Яблоки` -> `Yabloki`).

## 4. Режим 2: Онлайн-интеграция (Сетевой Scale Agent по WebSocket и REST)

Для полностью автоматической синхронизации весов без ручного скачивания файлов разработана архитектура **Scale Agent**.

### Схема взаимодействия

```
┌──────────────┐             REST / WebSocket            ┌──────────────────┐
│              │ ◄─────────────────────────────────────► │                  │
│    NurCRM    │  1. GET /scales/token/ (получить токен) │   Scale Agent    │
│   Backend    │  2. POST /scales/register/ (регистрация)│ (Сервис на ПК    │
│   (Django    │  3. WS connect ws/agents/?token=...     │  в магазине)     │
│   Channels)  │ ──────────────────────────────────────► │                  │
│              │  4. Command: plu_batch (пакет PLU)      │                  │
└──────────────┘                                         └─────────┬────────┘
                                                                   │ TCP Port 4001
                                                                   ▼
                                                          ┌──────────────────┐
                                                          │   Весы в LAN     │
                                                          │  (Rongta / CAS)  │
                                                          └──────────────────┘
```

### Аутентификация агента: `scale_api_token`
Агент авторизуется с помощью постоянного токена компании. Токен генерируется в профиле компании:
`GET /api/users/scales/token/`
```json
{
  "scale_api_token": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```
В последующих запросах агент передает заголовок:
`Authorization: Bearer a1b2c3d4-e5f6-7890-abcd-ef1234567890`

---

### REST API агента весов

#### 1. Регистрация весов в системе
`POST /api/users/scales/register/`

**Тело запроса:**
```json
{
  "token": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "name": "Весы Торговый зал 1",
  "ip": "192.168.1.120"
}
```

**Ответ:**
```json
{
  "id": "7fa8b9c0-1234-5678-90ab-cdef12345678",
  "created": true,
  "company": "company-uuid"
}
```

#### 2. Запрос списка весовых товаров агентом
`GET /api/users/scales/products/`
Заголовок: `Authorization: Bearer <scale_api_token>`

Возвращает активные весовые и штучные товары компании для загрузки в весы.

#### 3. Отправка товаров в весы из CRM
`POST /api/users/scales/send-products/`
Доступ: Авторизованный сотрудник компании.

**Тело запроса:**
```json
{
  "product_ids": ["uuid1", "uuid2"],
  "plu_start": 1
}
```
Эндпоинт:
- Блокирует выдачу PLU транзакционным замком компании.
- Назначает свободные PLU товарам.
- Формирует пакет `plu_batch`.
- Отправляет сообщение в WebSocket-группу `scale_company_<company_id>`.

---

### WebSocket-канал: `ws/agents/`
URL: `ws://<domain>/ws/agents/?token=<scale_api_token>`

Обработчик: `apps/scale/consumers.py` (`AgentScaleConsumer`).

При подключении агент добавляется в группу Channels `scale_company_<company_id>` и получает приветственное сообщение:
```json
{
  "type": "hello",
  "company_id": "company-uuid"
}
```

    },
    {
      "product_uuid": "4fa85f64-5717-4562-b3fc-2c963f66afa7",

## 5. Чтение весовых штрихкодов на кассе (POS) и складе

Когда кассир сканирует этикетку на кассе (`POST /api/main/pos/sales/<cart_id>/scan/`) или кладовщик проверяет товар на складе (`GET /api/main/products/warehouse-barcode/<barcode>/`), система анализирует 13-значный штрихкод стандарта EAN-13.

### Формат штрихкодов EAN-13
Весовой штрихкод состоит из 13 цифр:
```
┌─────────┬─────────────┬─────────────┬────────┐
│ Префикс │   Код PLU   │   Значение  │ Чексумма
│ 2 цифры │ 5 или 6 цифр│ 5 или 4 цифр│ 1 цифра│
└─────────┴─────────────┴─────────────┴────────┘
```

- **Префикс (2 цифры):** Диапазон `20`–`29` (выделен стандартом EAN для локального использования предприятиями).
  - По умолчанию в NurCRM: `20` = весовой товар, `25` = суммовой товар.
  - Если на весах задан отдел `21`, префикс будет `21`.

---

### Раскладки: `plu` vs `code`

| Раскладка (`scale_barcode_layout`) | Структура EAN-13 | Пример ШК: `2000001005406` |
|---|---|---|
| **`plu`** (по умолчанию) | `PP` (2) + `PLU` (5) + `ЗНАЧЕНИЕ` (5) + `C` (1) | Префикс `20`, **PLU = 1**, Значение = `00540` |
| **`code`** | `PP` (2) + `PLU` (6) + `ЗНАЧЕНИЕ` (4) + `C` (1) | Префикс `20`, **PLU = 10**, Значение = `0540` |

---

### Режимы: `auto`, `weight`, `amount`
Настройка `Company.scale_barcode_mode` определяет, как трактовать поле значения:

1. **`weight` (по весу):**
   Значение всегда считается весом в граммах.
   `00540` -> 540 грамм -> **`0.540 кг`**.
   Цена строки чека = `0.540 × цена_товара`.

2. **`amount` (по сумме):**
   Значение считается итоговой стоимостью взвешенного товара.
   Применяется, когда весы запрограммированы печатать сумму вместо веса.
   Вес вычисляется делением суммы на цену товара за 1 кг.

3. **`auto` (автоматически по префиксу):**
   - Если префикс `20` -> режим `weight`.
   - Если префикс `25` -> режим `amount`.

---

### Единицы суммы: `tiyin` vs `som`
Применяется, если штрихкод содержит сумму (`mode = amount` или `auto` с суммовым префиксом):

| Значение (`scale_barcode_amount_unit`) | Правило деления | Пример в поле ШК | Итоговая сумма |
|---|---|---|---|
| **`tiyin`** (дефолт) | Делится на 100 (2 знака копеек) | `03800` | **38.00 сом** |
| **`som`** | Сумма в целых сомах (без деления) | `00036` | **36.00 сом** |

### Алгоритм обратного восстановления веса из суммы

#### Проблема отбрасывания копеек на весах
При печати этикетки со стоимостью весы Rongta отбрасывают дробную часть суммы:
> *Пример:* Бананы 540 сом/кг. Взвешено **0.170 кг**.
> Точная сумма: `0.170 × 540 = 91.80 сом`.
> На этикетке весы печатают целое число: **91 сом** (штрихкод зашивает `91`).
> Если выполнить стандартный расчет: `91 / 540 = 0.168518... кг` -> округлится до **`0.169 кг`**.
> Возникает систематическая недостача в 1 грамм (кассир видит 0.169 вместо 0.170)!

#### Решение в NurCRM (`_weight_from_amount`)
Код: `apps/main/pos_views.py` (строки 924–967)

NurCRM использует дискретную сетку торговых весов:
1. Шаг дискретности торговых весов 6/15 кг составляет **5 грамм** (`SCALE_WEIGHT_STEP_KG = 0.005`).
2. Напечатанная сумма $A$ определяет интервал допустимых весов:
   $$\left[ \frac{A}{\text{цена}}, \frac{A + \text{шаг суммы}}{\text{цена}} \right)$$
3. Система ищет количество точек сетки $N \times 0.005$, попадающих в данный интервал.
4. Если в интервал попадает **ровно один физический вес**, система автоматически привязывается к нему и восстанавливает **0.170 кг** с абсолютной точностью!

### Двойной Fallback раскладок при сканировании
Если в настройках компании случайно выбрана раскладка `plu`, а весы запрограммированы на 6-значный `code` (или наоборот), касса не выдает ошибку сразу:
1. Выполняется поиск товара по основной раскладке компании.
2. Если товар с таким PLU не найден, система автоматически пробует альтернативную раскладку.
3. Товар находится без прерывания работы кассира, а в системный журнал пишется сервисное предупреждение для администратора.

## 6. Пошаговая инструкция по настройке оборудования (на примере Rongta RLS1100)

### Шаг 1. Настройка весовых товаров в NurCRM
1. Перейдите в раздел **Товары / Склад**.
2. При создании или редактировании товара включите тумблер **«Весовой товар»** (`is_weight = true`).
3. Укажите единицу измерения `кг` и цену за 1 кг.
4. Поле **PLU** можно оставить пустым — система назначит его автоматически.

### Шаг 2. Настройка чтения штрихкодов в NurCRM
1. Перейдите в **Настройки компании** -> блок **«Весы»**.
2. Для стандартных весов Rongta RLS1100 с заводской прошивкой рекомендуется:
   - **Режим значения (`scale_barcode_mode`):** `По весу (weight)`
   - **Раскладка (`scale_barcode_layout`):** `По PLU (plu)` или `По коду (code)` (согласно выбранному формату этикетки)
   - **Единица суммы (`scale_barcode_amount_unit`):** `Тыйын` (или `Сом`, если весы печатают сумму без тийынов)
3. Сохраните изменения.

### Шаг 3. Выгрузка каталога товаров
1. Нажмите кнопку **«Экспорт для весов»** (или выполните запрос к `/api/main/products/scale-export/`).
2. Сохраните файл с расширением `.TXP`.

### Шаг 4. Импорт в весы через ПО Rongta (RLS PLU Manager)
1. Подключите весы к локальной сети через Ethernet-кабель. Задайте весам IP-адрес (например `192.168.1.150`).
2. Откройте программу **RLS PLU Management** (RTPLU).
3. Добавьте устройство с IP-адресом весов.
4. Выберите пункт меню **Import / Импорт** -> укажите скачанный `.TXP` файл.
5. Нажмите **Download to Scale / Загрузить в весы**.
6. После завершения прошивки распечатайте тестовую этикетку на весах.

### Шаг 5. Проверка сканирования на кассе
1. Откройте рабочее место кассира (POS).
2. Отсканируйте штрихкод с распечатанной этикетки.
3. Товар должен мгновенно появиться в корзине с рассчитанным весом в поле «Количество».

## 7. Типовые сценарии, ошибки и Troubleshooting

| Проблема / Ошибка | Причина | Решение |
|---|---|---|
| **При сканировании вес умножается на 10 или делится на 10** | Не совпадает раскладка (`plu` 5 знаков vs `code` 6 знаков). | В настройках компании смените `scale_barcode_layout` с `plu` на `code` (или наоборот). |
| **Товар добавляется с весом 36 г вместо реального веса, на этикетке сумма 36 сом** | Весы зашили в штрихкод сумму, а в CRM включен режим веса. | Переключите `scale_barcode_mode` в `amount`, а `scale_barcode_amount_unit` в `som`. |
| **Ошибка 404: «Товар с PLU X не найден»** | После создания товара файл не был выгружен в весы, либо PLU на весах рассинхронизирован. | Повторите экспорт через `/api/main/products/scale-export/` и загрузите файл в весы. |
| **Ошибка 404: «Невозможно рассчитать вес: у товара не указана цена»** | Штрихкод суммовой, но в карточке товара розничная цена пустая или равна 0. | Заполните цену товара в CRM. |
| **Программа весов падает с ошибкой Access Violation при импорте** | В файле присутствуют строки с длиной имени более 36 символов или некорректные спецсимволы. | Используйте штатный экспорт `/scale-export/` — он автоматически обрезает имена до 36 символов и очищает управляющие символы. |
| **На дисплее весов вместо букв отображаются `????`** | Прошивка весов не поддерживает кириллицу (Unicode). | При экспорте убедитесь, что параметр `translit=1` включен (по умолчанию активен). |
| **Агент весов не может подключиться к WebSocket (`code=4001` или `4002`)** | Не передан параметр `?token=` в query-строке, либо передан неверный токен. | Проверьте `scale_api_token` компании через `GET /api/users/scales/token/`. |
