# Сырьё, обработка и себестоимость готовой продукции (для фронта)

База: `/api/main/`

Документ описывает цепочку **производства**:

1. Оприходование сырья на склад (`items-make`)
2. Обработка сырья с учётом потерь (очистка, нарезка и т.д.)
3. Создание готовой продукции с рецептом и авто-расчётом себестоимости (`products/create-manual`)

---

## 0) Общие правила

- Авторизация: `Authorization: Bearer <token>` (как во всём `/api/main/`)
- Все количества и цены передаются **строками** (Decimal), например `"100.000"`, `"45.00"`
- Данные фильтруются по **компании** и **активному филиалу** пользователя
- Существующие записи `ItemMake` без обработки имеют `kind: "raw"` (миграция проставляет default)

### Типы сырья (`kind`)

| Значение      | Описание                                      |
|---------------|-----------------------------------------------|
| `raw`         | Необработанное сырьё (закупка, оприходование) |
| `processed`   | Обработанное сырьё (после очистки, нарезки)   |

## 1) Сценарий целиком (UI-flow)

```
┌─────────────────────────────────────────────────────────────────┐

└───────────────────────────┬─────────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│  Шаг 3. Выбрать обработанное сырьё в рецепте                    │

                            ▼

│  recipe + calc_purchase_price_from_recipe → себестоимость авто   │

```

## 2) ItemMake — сырьё на складе

### 2.1) `GET /api/main/items-make/`

Список позиций сырья.

**Query-параметры:**

| Параметр   | Описание                                      |
|------------|-----------------------------------------------|
| `kind`     | `raw` или `processed` — фильтр по типу        |
| `search`   | Поиск по названию, поставщику, связанным товарам |
| `unit`     | Единица измерения                             |
| `ordering` | `-created_at`, `name`, `price`, `quantity`  |

**Пример — только обработанное сырьё (для выпадающего списка в рецепте):**

```
GET /api/main/items-make/?kind=processed
```

**Ответ (массив):**

```json
[
  {
    "id": "a1b2c3d4-....",
    "company": "34ff2664-....",
    "branch": null,
    "kind": "processed",
    "kind_display": "Обработанное",
    "is_processed": true,
    "source": "62dc477e-fde9-4fb3-8daa-220b6029a542",
    "source_name": "картошка",
    "name": "картошка (очищенная)",
    "supplier": null,
    "supplier_name": null,
    "price": "50.00",
    "unit": "кг",
    "quantity": "90.000",
    "products": [],
    "created_at": "2026-05-31T23:00:00+06:00",
    "updated_at": "2026-05-31T23:00:00+06:00"
  }
]
```

**Поля для UI:**

| Поле           | Read | Write | Комментарий                              |
|----------------|------|-------|------------------------------------------|
| `kind`         | ✅   | ❌    | `raw` / `processed`                      |
| `is_processed` | ✅   | ❌    | shorthand: `kind === "processed"`        |
| `source`       | ✅   | ❌    | UUID исходного сырья (только processed)  |
| `source_name`  | ✅   | ❌    | Название исходного сырья                 |
| `price`        | ✅   | ✅    | Цена за единицу (`unit`)                 |
| `quantity`     | ✅   | ✅    | Остаток на складе                        |
| `unit`         | ✅   | ✅    | `кг`, `шт.`, `л` и т.д.                  |

---

### 2.2) `POST /api/main/items-make/`

Создание **сырого** сырья (оприходование).

**Body:**

```json
{
  "name": "картошка",
  "price": "45.00",
  "unit": "кг",
  "quantity": "100.000",
  "supplier": "uuid-поставщика"
}
```

`supplier` — опционально, UUID клиента с типом «Поставщики».

**Ответ `201`:** объект `ItemMake` с `kind: "raw"`.

> При создании через POST поле `kind` всегда `raw`. Обработанное сырьё создаётся **только** через `/process/`.

---

### 2.3) `GET/PATCH/DELETE /api/main/items-make/<uuid:pk>/`

Стандартный CRUD. При PATCH можно менять `name`, `price`, `quantity`, `unit`, `supplier`.

`kind` и `source` — **read-only** (не меняются через PATCH).

## 3) Обработка сырья

### `POST /api/main/items-make/<uuid:pk>/process/`

`<pk>` — UUID **сырого** сырья (`kind=raw`).

Списывает `input_quantity` с исходной позиции и зачисляет `output_quantity` в обработанную.

**Body:**

```json
{
  "input_quantity": "100.000",
  "output_quantity": "90.000",
  "name": "картошка (очищенная)",
  "processing_cost": "0.00",
  "target_item_make_id": null
}
```

| Поле                  | Обяз. | Описание                                              |
|-----------------------|-------|-------------------------------------------------------|
| `input_quantity`      | ✅    | Сколько списать с сырого сырья (> 0)                  |
| `output_quantity`     | ✅    | Сколько получить обработанного (> 0, ≤ input)         |
| `name`                | ❌    | Название обработанной позиции. Default: `{name} (обработанное)` |
| `processing_cost`     | ❌    | Доп. стоимость обработки за партию (default `0.00`)   |
| `target_item_make_id` | ❌    | UUID существующей processed-позиции для пополнения    |

**Формула цены обработанного сырья (новая партия):**

```
batch_price = (input_quantity × source.price + processing_cost) / output_quantity
```

**Пример:** 100 кг × 45 сом = 4500 → 4500 / 90 = **50.00** сом/кг

**При пополнении существующей processed-позиции (`target_item_make_id`):**

```
new_price = (old_qty × old_price + input_qty × source.price + processing_cost) / (old_qty + output_qty)
```

**Ответ `201`:**

```json
{
  "source": {
    "id": "62dc477e-....",
    "kind": "raw",
    "name": "картошка",
    "price": "45.00",
    "quantity": "0.000",
    "unit": "кг"
  },
  "processed": {
    "id": "f8e9....",
    "kind": "processed",
    "is_processed": true,
    "source": "62dc477e-....",
    "source_name": "картошка",
    "name": "картошка (очищенная)",
    "price": "50.00",
    "quantity": "90.000",
    "unit": "кг"
  }
}
```

**Ошибки `400`:**

| Ключ / поле              | Причина                                           |
|--------------------------|---------------------------------------------------|
| `detail`                 | «Обрабатывать можно только необработанное сырьё»  |
| `detail`                 | «Недостаточно сырья …»                            |
| `output_quantity`        | «Выход не может быть больше входа»                |
| `target_item_make_id`    | «Обработанное сырьё не найдено»                   |

## 4) Создание готовой продукции с рецептом

### `POST /api/main/products/create-manual/`

Создаёт товар, сохраняет рецепт, **списывает сырьё** со склада и (опционально) считает себестоимость.

### 4.1) Рецепт (`recipe`)

Массив позиций — расход сырья **на 1 единицу** готового товара.

```json
"recipe": [
  {
    "id": "f8e9....",
    "qty_per_unit": "0.100"
  },
  {
    "id": "другой-uuid-сyrья",
    "qty_per_unit": "1.000"
  }
]
```

| Поле           | Описание                                    |
|----------------|---------------------------------------------|
| `id`           | UUID `ItemMake` (рекомендуется `processed`) |
| `qty_per_unit` | Расход сырья на 1 шт. готовой продукции (> 0) |

> **Важно для UI:** в выпадающем списке рецепта показывайте `GET /items-make/?kind=processed`.  
> Можно использовать и `raw`, но тогда себестоимость будет без учёта потерь при обработке.

### 4.2) Авто-расчёт себестоимости

**Флаг:** `calc_purchase_price_from_recipe`

| Значение | Поведение |
|----------|-----------|
| `true` (default) | Если `purchase_price` **не передан** — считается из рецепта |
| `false`          | Используется переданный `purchase_price` |

**Формула:**

```
purchase_price = Σ (qty_per_unit × item_make.price) по всем позициям recipe
```

**Пример:** 0.1 кг обработанной картошки @ 50 сом/кг → `purchase_price = "5.00"`

**Логика цены продажи** (как раньше):

- Если передан `price` → пересчитывается `markup_percent`
- Если `price` не передан → `price = purchase_price × (1 + markup_percent / 100)`

### 4.3) Полный пример запроса

```json
{
  "name": "Крекер солёный Сметана и лук 100г",
  "barcode": "3533008225900",
  "brand_name": "бургер",
  "category_name": "острый",
  "unit": "шт.",
  "quantity": "100",
  "calc_purchase_price_from_recipe": true,
  "markup_percent": "1350",
  "recipe": [
    {
      "id": "f8e9-processed-картошка",
      "qty_per_unit": "0.100"
    }
  ]
}
```

**Что произойдёт:**

1. `purchase_price` = 0.1 × 50 = **5.00**
2. `price` = 5 × (1 + 1350/100) = **72.50** (если `price` не передан)
3. Со склада спишется: `0.100 × 100 шт = 10 кг` обработанной картошки

### 4.4) Ответ — новые поля рецепта

```json
{
  "id": "c173b3cd-....",
  "name": "Крекер солёный Сметана и лук 100г",
  "purchase_price": "5.00",
  "markup_percent": "1350.0000",
  "price": "72.50",
  "quantity": "100.00",
  "item_make": [
    {
      "id": "f8e9....",
      "name": "картошка (очищенная)",
      "price": "50.00",
      "unit": "кг",
      "quantity": "80.000",
      "kind": "processed",
      "kind_display": "Обработанное",
      "source": "62dc477e-....",
      "source_name": "картошка"
    }
  ],
  "recipe": [
    {
      "id": "f8e9....",
      "name": "картошка (очищенная)",
      "qty_per_unit": "0.100",
      "unit": "кг",
      "unit_price": "50.00",
      "line_cost": "5.00"
    }
  ]
}
```

| Поле рецепта  | Описание                              |
|---------------|---------------------------------------|
| `qty_per_unit`| Расход на 1 ед. готового товара       |
| `unit_price`  | Цена сырья за единицу (`ItemMake.price`) |
| `line_cost`   | `qty_per_unit × unit_price` — вклад в себестоимость |

**Сумма `line_cost` по всем позициям = `purchase_price`** (если авто-расчёт включён).

### 4.5) Ошибки рецепта `400`

```json
{ "recipe": "Недостаточно сырья «картошка (очищенная)»: требуется 10.000, доступно 8.000." }
```

```json
{ "recipe": "Сырьё не найдено или принадлежит другой компании: [\"uuid\"]" }
```

## 5) Рекомендации для UI

### Экран «Склад сырья»

- Таблица с колонками: название, тип (`kind_display`), остаток, цена, единица
- Фильтр: «Все / Сырьё / Обработанное»
- Кнопка «Обработать» только для строк с `kind=raw` и `quantity > 0`

### Модалка обработки

```
Исходное сырьё:  картошка — 100 кг @ 45 сом
Вход (списать):  [100.000] кг
Выход (получить):[90.000]  кг
Потери:           10 кг (10%)   ← считать на фронте: input - output
Доп. расход:     [0.00] сом
Название:        [картошка (очищенная)]
Цена за кг:      50.00 сом      ← preview: (input×price+cost)/output
```

Preview цены можно считать на клиенте по той же формуле — бэкенд пересчитает при сохранении.

### Экран «Создание продукции»

1. Блок **«Состав (рецепт)»** — мультиселект из `GET /items-make/?kind=processed`
2. Для каждой строки: `qty_per_unit` (расход на 1 шт.)
3. Блок **«Себестоимость»**:
   - Toggle «Считать из рецепта» (`calc_purchase_price_from_recipe`)
   - Live-preview: `Σ qty_per_unit × price` при изменении рецепта
4. Поле «Количество партии» (`quantity`) — от него зависит **списание** со склада:
   ```
   списание = qty_per_unit × quantity
   ```
5. Показывать предупреждение, если остатка сырья не хватает (можно пре-валидировать на фронте)

### PATCH продукции

`PATCH /api/main/products/<uuid:pk>/` — рецепт и списание работают как раньше (дельта по изменению quantity/recipe).  
Авто-пересчёт `purchase_price` при PATCH **не добавлен** — только при `create-manual`.

## 6) Числовые типы

| Поле              | Decimal places |
|-------------------|----------------|
| `quantity` (ItemMake) | 3          |
| `qty_per_unit`    | 3              |
| `price`, `purchase_price`, `line_cost` | 2 |

Передавайте строки: `"0.100"`, не `0.1` (float).

---

## 7) Миграция (деплой)

На сервере после обновления бэкенда:

```bash
python manage.py migrate main
```

Без миграции поля `kind` / `source` будут отсутствовать в БД.
