# Продажа пачки поштучно (сигареты и аналоги)

Документ описывает, как в Market POS учитывается товар, у которого **остаток на складе ведётся в пачках** (или другой «упаковке»), а на кассе нужно продавать **отдельные штуки**.

Связанные файлы в коде: `apps/main/models.py` (`ProductPackage`, `CartItem.sale_package`, `SaleItem.sale_package`), `apps/main/pos_utils.py`, `apps/main/services/__init__.py` (`checkout_cart`), `apps/main/pos_views.py` (`SaleAddItemAPIView`).

---

## Зачем это нужно

- У товара `Product.quantity` хранится, например, в **пачках** (одна строка остатка = одна пачка).
- Покупатель может взять **3 сигареты** из пачки: в корзине `quantity = 3`, но со склада нужно списать **долю пачки**, а не три «пачки».

Без `sale_package` поле `quantity` в строке корзины считается в **той же единице**, что и склад (обычно целые пачки).

---

## Модель упаковки: `ProductPackage`

Для товара заводится запись упаковки (`ProductPackage`):

| Поле | Смысл |
|------|--------|
| `product` | Товар, к которому относится упаковка |
| `name` | Подпись (например, «Пачка») |
| `quantity_in_package` | **Сколько «штук» в одной учётной единице** (для сигарет в пачке — обычно `20`) |

`quantity_in_package` **обязан быть > 0**, иначе поштучная продажа по этой упаковке невозможна (ошибка при чекауте и при проверке остатка).

---

## Строка корзины: `CartItem.sale_package`

- **`sale_package = null`** — обычная строка: `quantity` в учётных единицах товара (как на складе), например целые пачки.
- **`sale_package = <uuid ProductPackage>`** — **поштучная продажа из этой упаковки**:
  - `quantity` — **количество штук** (сигарет), не пачек;
  - списание с `Product.quantity` считается в «пачках».

В одной корзине для одного и того же товара могут быть **две независимые строки**:

1. Пачки: `sale_package = null`, `quantity = 2` → минус 2 с учётного остатка.
2. Штуки из пачки: `sale_package = <пачка>`, `quantity = 5` → минус `5 / quantity_in_package` с учётного остатка.

Ограничения уникальности в модели не дают дублировать одну и ту же комбинацию `(корзина, товар, упаковка)` для поштучных строк и `(корзина, товар)` без упаковки для «пачечной» строки.

---

## Списание остатка

Функция `cart_item_stock_consume_units` (`apps/main/pos_utils.py`):

- без `sale_package`: списание = `quantity` (с округлением до 3 знаков);
- с `sale_package`: списание = **`quantity / quantity_in_package`** (округление до 3 знаков).

Пример: в пачке 20 шт., продали 5 шт. → со склада списывается **0.25** учётной единицы (четверть пачки).

При добавлении в корзину остаток проверяется **суммарно по всем строкам** этого товара через `total_cart_consume_packs_for_product`: и пачки, и поштучные строки переводятся в одни «условные пачки» и сравниваются с `Product.quantity`.

---

## Цены и закупка

- **Цена по умолчанию за штуку** (если не передали `unit_price`):  
  `default_unit_price_for_package` = **`product.price / quantity_in_package`** (цена пачки делится на число штук в пачке).
- **Минимальная продажная (без скидки на строку):** закупочная за штуку = **`purchase_price / quantity_in_package`** (аналогично в `CartItem.clean` и в `SaleAddItemAPIView`).

Эффективная цена за штуку по-прежнему:  
`unit_price - (line_discount / quantity)`.

---

## API: добавление в корзину (обычная касса)

**POST** `/api/main/pos/sales/<cart_id>/add-item/`

Дополнительное поле тела запроса:

| Поле | Обязательное | Описание |
|------|--------------|----------|
| `sale_package_id` | нет | UUID `ProductPackage` этого товара и компании. Если передан — строка считается **поштучной** из указанной упаковки. |

Пример: 7 сигарет из пачки по 20 шт.

```json
{
  "product_id": "<uuid товара>",
  "quantity": "7.000",
  "sale_package_id": "<uuid ProductPackage с quantity_in_package=20>"
}
```

В ответе корзины у позиции в поле `sale_package` приходит тот же UUID (read-only в сериализаторе позиции).

---

## Чекаут

Поштучное списание и перенос `sale_package` в чек выполняются только в **`checkout_cart`** (`apps/main/services/__init__.py`):

- требуется **открытая смена** у корзины (`shift`);
- для каждой строки вызывается `cart_item_stock_consume_units`;
- в `SaleItem` сохраняются `sale_package_id` и `purchase_price_snapshot` (за штуку: закупка пачки / `quantity_in_package`).

---

## Агентская корзина

Поштучная продажа из упаковки **не поддерживается** в агентском потоке:

- **POST** `/api/main/agents/me/carts/<cart_id>/add-item/` — при передаче `sale_package_id` возвращается **400** с пояснением;
- **`checkout_agent_cart`** — если в корзине уже есть позиция с `sale_package`, выбрасывается **ValidationError**.

Оформление только через обычную кассу со сменой и `checkout_cart`.

---

## Чеклист для внедрения на товаре

1. У товара заведена упаковка `ProductPackage` с корректным `quantity_in_package`.
2. На кассе при продаже «шт из пачки» передаётся `sale_package_id` этой упаковки.
3. Для продажи целыми пачками `sale_package_id` не передаётся (как раньше).

Подробности общего API корзины см. [MARKET_POS_CART_FRONTEND_API.md](./MARKET_POS_CART_FRONTEND_API.md).
