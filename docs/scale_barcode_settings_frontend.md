# Весы — Настройки чтения штрихкода (режим + раскладка)

Два переключателя на уровне компании, которые управляют тем, как касса разбирает штрихкод весов. Нужны, потому что разные весы кодируют штрихкод по-разному.

**Эндпоинт:** `/api/users/settings/company/` — компания текущего пользователя.
- `GET` — прочитать текущие настройки.
- `PATCH` — изменить (owner/admin).

**Статус:** бэкенд готов. `scale_barcode_layout` — новое поле, **нужна миграция на сервере**.

---

## 1. Поля

| Поле | Значения | Что задаёт |
|---|---|---|
| `scale_barcode_mode` | `auto` \| `weight` \| `amount` | Что зашито в поле значения: вес (граммы) или сумма (сомы). `auto` — по префиксу (20=вес, 25=сумма) |
| `scale_barcode_layout` | `plu` \| `code` | **Раскладка полей штрихкода** (см. ниже) |

### `scale_barcode_layout`

Обе раскладки ищут товар по **`Product.plu`** — отличаются только шириной полей:
- **`plu`** (по умолчанию): `префикс(2) + PLU(5) + вес/сумма(5) + чек(1)`.
- **`code`**: `префикс(2) + PLU(6) + вес(4) + чек(1)`. Значение всегда трактуется как вес (граммы / 1000).

> В выгрузке для весов колонка «Код» = PLU (реальные `Product.code` бывают слишком большими и не влезают в поле штрихкода). Поэтому «по коду» = то же PLU, но в 6-значном поле.

Как понять, какая раскладка у ваших весов: свесьте товар с известным PLU и посмотрите штрихкод — сколько цифр занимает номер товара (5 или 6) и вес (5 или 4). Если касса читает «не тот PLU» в раскладке `plu` — переключите на `code`.

## 2. Прочитать настройки

```
GET /api/users/settings/company/
Authorization: Bearer <token>
```
В ответе среди прочих полей компании:
```json
{
  "scale_barcode_mode": "auto",
  "scale_barcode_layout": "plu"
}
```

## 3. Изменить

```
PATCH /api/users/settings/company/
Authorization: Bearer <token>
Content-Type: application/json

{ "scale_barcode_layout": "code", "scale_barcode_mode": "weight" }
```
Можно слать по одному полю. Ответ — обновлённый объект компании.

## 4. UI — что показать

Экран «Настройки весов» (или в настройках компании), два селекта:

**Раскладка штрихкода** (`scale_barcode_layout`):
- «По PLU» → `plu`
- «По коду» → `code`

**Режим значения** (`scale_barcode_mode`):
- «Авто (по префиксу)» → `auto`
- «По весу» → `weight`
- «По сумме» → `amount`

Пример вызова:
```js
await api.patch("/users/settings/company/", {
  scale_barcode_layout: layout,   // "plu" | "code"
  scale_barcode_mode: mode,       // "auto" | "weight" | "amount"
});
```

## 5. Типовые связки

| Ситуация | layout | mode |
|---|---|---|
| Весы печатают `20 + PLU(5) + вес(5)` | `plu` | `weight` (или `auto`) |
| Весы печатают `21 + PLU(6) + вес(4)` | **`code`** | `weight` |
| Смешанные весовые/итоговые ШК с префиксами 20/25 | `plu` | `auto` |

Для весов Rongta RLS из нашего экспорта (отдел 21, тип штрихкода 5) обычно: **`layout = code`, `mode = weight`**.

## 6. Важно

- Настройка на **всю компанию** — применяется ко всем кассам этой компании.
- После смены изменения действуют сразу на следующем скане (перезагрузка не нужна).
- Если PLU распознаётся, но не находится товар — значит PLU из штрихкода не совпадает с `Product.plu` в базе; сверьте, что выгрузка PLU в весы и товары в системе согласованы.
