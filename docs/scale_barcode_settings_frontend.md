# Весы — Настройки чтения штрихкода (режим + раскладка + единица суммы)

Три переключателя на уровне компании, которые управляют тем, как касса разбирает штрихкод весов. Нужны, потому что разные весы кодируют штрихкод по-разному.

**Эндпоинт:** `/api/users/settings/company/` — компания текущего пользователя.
- `GET` — прочитать текущие настройки.
- `PATCH` — изменить. Доступ: любой авторизованный сотрудник компании (отдельной проверки на owner/admin на бэке нет — ограничивайте показ экрана на фронте).

**Статус:** бэкенд готов. `scale_barcode_amount_unit` — новое поле, **нужна миграция на сервере** (`users.0046_company_scale_barcode_amount_unit`).

---

## 1. Поля

| Поле | Значения | Дефолт | Что задаёт |
|---|---|---|---|
| `scale_barcode_mode` | `auto` \| `weight` \| `amount` | `auto` | Что зашито в поле значения: **вес** (граммы) или **сумма**. `auto` — по префиксу (20 = вес, 25 = сумма) |
| `scale_barcode_layout` | `plu` \| `code` | `plu` | **Раскладка полей** штрихкода (ширина полей PLU и значения) |
| `scale_barcode_amount_unit` | `tiyin` \| `som` | `tiyin` | **Единица суммы**. Работает только когда поле читается как сумма (`mode=amount`, либо `auto` + суммовой префикс) |

### `scale_barcode_layout`

Обе раскладки ищут товар по **`Product.plu`** — отличаются только шириной полей:
- **`plu`** (по умолчанию): `префикс(2) + PLU(5) + значение(5) + чек(1)`
- **`code`**: `префикс(2) + PLU(6) + значение(4) + чек(1)`

> В выгрузке для весов колонка «Код» = PLU (реальные `Product.code` бывают слишком большими и не влезают в поле штрихкода). Поэтому «по коду» = то же PLU, но в 6-значном поле.

Обе раскладки трактуют поле значения **одинаково** — по `scale_barcode_mode` (раньше `code` всегда означал вес).

Как понять, какая раскладка у ваших весов: свесьте товар с известным PLU и посмотрите штрихкод — сколько цифр занимает номер товара (5 или 6). **Если ошиблись — не страшно:** при промахе по основной раскладке касса автоматически пробует альтернативную. Настройка влияет на то, какая пробуется первой.

### `scale_barcode_amount_unit`

| Значение | Как читается поле | Пример |
|---|---|---|
| `tiyin` (дефолт) | Сумма в тыйынах, 2 знака после запятой (делится на 100) | `03800` → **38.00 сом** |
| `som` | Сумма целыми сомами | `00036` → **36 сом** |

Как понять, какое значение нужно: свесьте товар и сравните `Сумма(сом)` на этикетке с полем значения в штрихкоде. Если поле совпадает с суммой один-в-один (`36` и `00036`) — `som`. Если в поле два лишних нуля (`38.00` и `03800`) — `tiyin`.

## 2. Прочитать настройки

```
GET /api/users/settings/company/
Authorization: Bearer <token>
```
В ответе среди прочих полей компании:
```json
{
  "scale_barcode_mode": "auto",
  "scale_barcode_layout": "plu",
  "scale_barcode_amount_unit": "tiyin"
}
```

Те же три поля приходят и в `GET /api/users/company/` (общий объект компании) — если экран настроек уже тянет компанию оттуда, отдельный запрос не нужен.

## 3. Изменить

```
PATCH /api/users/settings/company/
Authorization: Bearer <token>
Content-Type: application/json

{
  "scale_barcode_mode": "amount",
  "scale_barcode_layout": "plu",
  "scale_barcode_amount_unit": "som"
}
```
Можно слать по одному полю. Ответ — обновлённый объект компании.

Ошибки:
- `400 {"scale_barcode_amount_unit": ["\"xxx\" is not a valid choice."]}` — прислано значение вне списка.
- `404` — пользователь не привязан ни к одной компании.

## 4. UI — что показать

Экран «Настройки весов» (или в настройках компании), три селекта:

**Режим значения** (`scale_barcode_mode`):
- «Авто (по префиксу: 20=вес, 25=сумма)» → `auto`
- «По весу» → `weight`
- «По сумме» → `amount`

**Раскладка штрихкода** (`scale_barcode_layout`):
- «По PLU (префикс + PLU(5) + значение(5))» → `plu`
- «По коду (префикс + PLU(6) + значение(4))» → `code`

**Единица суммы** (`scale_barcode_amount_unit`):
- «Тыйын (03800 = 38.00 сом)» → `tiyin`
- «Сом (00036 = 36 сом)» → `som`

> Третий селект имеет смысл только при `mode = amount` или `mode = auto`. При `mode = weight` его можно дизейблить/прятать с подсказкой «влияет только на суммовые штрихкоды».

Пример вызова:
```js
await api.patch("/users/settings/company/", {
  scale_barcode_mode: mode,               // "auto" | "weight" | "amount"
  scale_barcode_layout: layout,           // "plu" | "code"
  scale_barcode_amount_unit: amountUnit,  // "tiyin" | "som"
});
```

## 5. Типовые связки

| Ситуация | mode | layout | amount_unit |
|---|---|---|---|
| Весы печатают `20 + PLU(5) + вес(5)` | `weight` (или `auto`) | `plu` | — |
| Весы печатают `21 + PLU(6) + вес(4)` | `weight` | **`code`** | — |
| Смешанные весовые/итоговые ШК с префиксами 20/25 | `auto` | `plu` | по весам |
| Весы печатают **сумму целыми сомами** (см. пример ниже) | **`amount`** | `plu` | **`som`** |

Для весов Rongta RLS из нашего экспорта (отдел 21, тип штрихкода 5) обычно: **`mode = weight`, `layout = code`**.

### Пример: сумма целыми сомами

Этикетка «Банан вес»: `Нетто 0.190 кг`, `Цена 190 сом/кг`, `Сумма 36 сом`, штрихкод `2000001000366`.

Разбор: `20` + `00001` (PLU 1) + `00036` + `6`.

Префикс `20`, но весы зашили в поле **сумму**, а не вес. При дефолтных настройках касса прочитает это как **36 граммов** — неверно. Нужно `mode = amount` + `amount_unit = som`, тогда:
- сумма = **36 сом**;
- количество = 36 / 190 = **0.189 кг**.

> Расхождение с этикеткой (0.190 vs 0.189) неизбежно: веса в таком штрихкоде нет вообще, он восстанавливается делением суммы на цену за кг. Итог по строке будет 35.91 вместо 36.00. Если нужен ровно вес — весы надо перенастроить на печать веса, а не суммы.

## 6. Как это видно на скане

`POST /api/main/pos/sales/<cart_id>/scan/` c `{"barcode": "..."}`.

- Успех → `201` и обычный объект корзины (`sale`, `carts`, `active_sale_id`). Количество в строке уже посчитано из штрихкода — **`quantity` из запроса игнорируется** для весовых/суммовых ШК.
- `404 {"not_found": true, "message": "Товар с PLU 1 / кодом 00001 не найден"}` — штрихкод разобран, но такого `Product.plu` нет.
- `404 {"not_found": true, "message": "Товар не найден: проверены PLU 1 / 10 (штрихкод 2000001000366)"}` — пробовались обе раскладки, ни одна не дала товар.
- `404 {"not_found": true, "message": "Невозможно рассчитать вес: у товара не указана цена"}` — суммовой ШК, но у товара `price` пустая или 0. Делить сумму не на что.
- `409 {"ambiguous": true, "matches": [...]}` — штрихкод найден у нескольких товаров, нужен ручной выбор.

Сообщения из `404` можно показывать кассиру как есть — они уже на русском и подсказывают, что чинить.

## 7. Важно

- Настройка на **всю компанию** — применяется ко всем кассам этой компании.
- После смены изменения действуют сразу на следующем скане (перезагрузка не нужна).
- Смена `amount_unit` не влияет на весовые штрихкоды — только на те, что читаются как сумма.
- Если PLU распознаётся, но товар не находится — PLU из штрихкода не совпадает с `Product.plu` в базе; сверьте, что выгрузка PLU в весы и товары в системе согласованы.
