# Создание складского товара с поставщиком и закупкой в долг/предоплату (фронт)

Документ описывает, как с фронта создать **складской товар**, указать **поставщика** и
оформить закупку **в долг** или **с предоплатой**.

Все операции — в модуле **warehouse** (НЕ `main`). База: `/api/warehouse/...`.
Авторизация обязательна (Bearer-токен пользователя с компанией).

---

## Общая схема (3 запроса)

```
1) POST /api/warehouse/{warehouse_id}/products/     → создать товар (с supplier)
2) POST /api/warehouse/documents/purchase/          → создать закупку (черновик)
3) POST /api/warehouse/documents/{document_id}/post/ → провести закупку (применить долг/остаток/предоплату)
```

Долг перед поставщиком, приход на склад и денежный документ по предоплате появляются
**только после шага 3 (проведение)**. Шаг 2 создаёт документ в статусе `DRAFT` — он ещё
ни на что не влияет.

Если долг/предоплата не нужны (товар просто с поставщиком) — достаточно шага 1.

---

## Шаг 1. Создать товар

`POST /api/warehouse/{warehouse_id}/products/`

Тело (основные поля):

```json
{
  "name": "Кола 0.5",
  "supplier": "b1a2c3d4-0000-0000-0000-000000000000",
  "purchase_price": "100.000",
  "markup_percent": "20.000",
  "price": "120.000",
  "wholesale_price": "0.000",
  "unit": "шт.",
  "quantity": "0.000",
  "minimum_quantity": "10.000",
  "barcode": "4600000000001",
  "article": "COLA-05"
}
```

Поля, связанные с этой задачей:

| Поле | Тип | Обяз. | Описание |
|------|-----|-------|----------|
| `supplier` | uuid | нет | Поставщик — контрагент склада типа `SUPPLIER` или `BOTH`. Можно не передавать. |
| `minimum_quantity` | decimal | нет | Минимальный остаток (порог алерта «мало на складе»). |

- `supplier` должен быть контрагентом **той же компании**; иначе — ошибка валидации.
- Список поставщиков для выпадашки: `GET /api/warehouse/crud/counterparties/?type=SUPPLIER`
  (или `type=BOTH`).

Ответ (201) содержит созданный товар, в т.ч.:

```json
{
  "id": "5c5e38de-ce4c-4510-ab8e-2b09121ab8b9",
  "supplier": "b1a2c3d4-0000-0000-0000-000000000000",
  "supplier_name": "Мирлан Мега",
  "minimum_quantity": "10.000",
  ...
}
```

`id` из ответа → используем как `product` в шаге 2.

---

## Шаг 2. Создать закупку (черновик)

`POST /api/warehouse/documents/purchase/`

```json
{
  "counterparty": "b1a2c3d4-0000-0000-0000-000000000000",
  "warehouse_to": "<uuid склада-приёмника>",
  "payment_kind": "credit",
  "prepayment_amount": "500.00",
  "comment": "Закупка при создании товара",
  "items": [
    {
      "product": "5c5e38de-ce4c-4510-ab8e-2b09121ab8b9",
      "qty": "10",
      "price": "100"
    }
  ]
}
```

| Поле | Тип | Обяз. | Описание |
|------|-----|-------|----------|
| `counterparty` | uuid | да (для закупки в долг) | Поставщик — тот же, что в товаре. |
| `warehouse_to` | uuid | да | Склад, куда приходуется товар. |
| `payment_kind` | enum | да | `cash` — оплата сразу; `credit` — в долг (в т.ч. с предоплатой). |
| `prepayment_amount` | decimal | нет | Только при `payment_kind=credit`. Сумма предоплаты. |
| `items[].product` | uuid | да | Товар из шага 1. |
| `items[].qty` | decimal | да | Количество закупки. |
| `items[].price` | decimal | да | Цена закупки за единицу. |

Маппинг типа оплаты из формы:

| «Тип оплаты» на форме | payment_kind | prepayment_amount |
|-----------------------|--------------|-------------------|
| **Долг** | `credit` | `0` (или не передавать) |
| **Предоплата** | `credit` | сумма предоплаты (> 0) |

Правила:
- `doc_type` передавать НЕ нужно — эндпоинт `/purchase/` сам ставит тип `PURCHASE`.
- `prepayment_amount` допустим только при `payment_kind=credit` и **не может превышать**
  сумму документа (`total`), иначе — ошибка при проведении.
- `number`, `total`, `status` — read-only (сервер выставляет сам), слать не нужно.

Ответ (201): документ в статусе `DRAFT`, поле `id` → в шаг 3.

---

## Шаг 3. Провести закупку

`POST /api/warehouse/documents/{document_id}/post/`

Тело не требуется.

После проведения:
- остаток товара на `warehouse_to` увеличивается на `qty`;
- у поставщика формируется **долг** на сумму документа минус предоплата;
- при `prepayment_amount > 0` создаётся и проводится денежный документ на сумму предоплаты.

Отменить проведение (если нужно): `POST /api/warehouse/documents/{document_id}/unpost/`.

---

## Частые ошибки

| Симптом | Причина | Решение |
|---------|---------|---------|
| `{"company": "У пользователя не задана компания."}` | Запрос уходит в `main` или у пользователя нет компании | Использовать warehouse-эндпоинты; проверить, что у пользователя есть компания |
| `supplier` не сохранился | Товар создан не на warehouse-эндпоинте (`WarehouseProductSerializer`) | Создавать товар через `/api/warehouse/{warehouse_id}/products/` |
| Поставщик не виден в выпадашке | Контрагент не типа `SUPPLIER`/`BOTH` или другой компании | Создать/выбрать поставщика в `crud/counterparties/` с `type=SUPPLIER` |
| Долг/остаток не появились | Документ остался в `DRAFT` | Вызвать шаг 3 (`/post/`) |
| Ошибка про предоплату | `prepayment_amount` > суммы документа, или указан при `payment_kind=cash` | Уменьшить предоплату / выставить `payment_kind=credit` |

---

## Вспомогательные эндпоинты

- Список складов: `GET /api/warehouse/crud/warehouses/`
- Список поставщиков: `GET /api/warehouse/crud/counterparties/?type=SUPPLIER`
- Создать поставщика: `POST /api/warehouse/crud/counterparties/` c `{"name": "...", "type": "SUPPLIER"}`
- Список закупок: `GET /api/warehouse/documents/purchase/`
- Карточка товара: `GET /api/warehouse/products/{product_id}/`
