# Склад — Агент: несколько складов общего доступа

**Что изменилось:** при включённом общем доступе (`common_access_enabled=true`) владелец может назначить агенту **несколько складов**, а не один. Появилось поле `common_warehouses` (массив). Старое поле `common_warehouse` (один склад) продолжает работать.

**Статус:** бэкенд готов. **Перед проверкой на стенде применить миграцию** (`makemigrations warehouse && migrate`).

---

## 1. Эндпоинты (без изменений в путях)

| Метод и путь | Назначение |
|---|---|
| `POST /warehouse/agents/company-memberships/` | Владелец напрямую назначает агента (без заявки) |
| `PATCH /warehouse/agents/company-requests/{id}/common-access/` | Владелец меняет складской доступ активного агента |

Оба доступны только владельцу/админу.

## 2. Тело запроса

```json
{
  "common_access_enabled": true,
  "common_warehouses": ["8f5d5f2c-…", "1a2b3c4d-…", "9e8d7c6b-…"],
  "can_sell_wholesale": true,
  "can_sell_without_approval": false
}
```

Для `company-memberships/` дополнительно обязателен `user` (uuid пользователя).

Поля:

| Поле | Тип | Правило |
|---|---|---|
| `common_access_enabled` | bool | Включает общий доступ к складам |
| `common_warehouses` | `[uuid, …]` | Набор складов. **Непустой, если `common_access_enabled=true`** (иначе 400). Все склады — той же компании (иначе 400) |
| `common_warehouse` | uuid \| null | Legacy: один склад. Эквивалентно `common_warehouses: [uuid]`. Можно не слать, если используешь `common_warehouses` |
| `assigned_warehouse` | uuid \| null | Как раньше; на набор общего доступа больше не влияет |

Правила разрешения набора:

- Если передан `common_warehouses` — берётся он.
- Иначе если передан `common_warehouse` — берётся как список из одного.
- Иначе (ничего не передано в запросе) — остаётся текущий набор агента.
- При `common_access_enabled=false` набор очищается (оба поля становятся пустыми).

> Прежнее ограничение «общий доступ только к назначенному складу» **снято** — владелец явно выбирает любой набор складов компании.

## 3. Ответ

`common_warehouses` — полный набор; `common_warehouse` — первый из набора (для обратной совместимости).

```json
{
  "id": "798fb275-…",
  "company": "fb64c942-…",
  "user": "88e1ffe2-…",
  "user_display": "Мирлан Мейманбеков",
  "status": "active",
  "assigned_warehouse": "8f5d5f2c-…",
  "common_access_enabled": true,
  "common_warehouse": "8f5d5f2c-…",
  "common_warehouses": ["8f5d5f2c-…", "1a2b3c4d-…", "9e8d7c6b-…"],
  "can_sell_wholesale": true,
  "can_sell_without_approval": false,
  "created_at": "2026-07-15T13:21:40+06:00",
  "updated_at": "2026-07-15T13:25:10+06:00"
}
```

## 4. На что это влияет

- **Остатки агента** `GET /warehouse/agents/my/products/` при включённом общем доступе показывают товары **со всех** складов из `common_warehouses` (раньше — с одного). `warehouse_id` в каждой строке указывает, с какого склада позиция. Пагинация и `?search=` работают как прежде.
- Продажа с общего остатка разрешена, если склад входит в набор агента.

## 5. Рекомендации фронту

- В форме доступа агента заменить одиночный выбор склада на мультиселект, привязанный к `common_warehouses`.
- Слать `common_warehouses` (массив). `common_warehouse` отдельно передавать не нужно — он проставится сам.
- Старые агенты, у которых был один склад, продолжат работать без изменений: бэкенд читает их единственный склад через fallback, а в ответе он придёт и в `common_warehouse`, и в `common_warehouses`.

## 6. Ошибки

| Ситуация | Ответ |
|---|---|
| `common_access_enabled=true`, пустой `common_warehouses` | 400 `{"common_warehouses": ["Укажите хотя бы один склад, если включён общий доступ."]}` |
| Склад из набора — другой компании | 400 `{"common_warehouses": ["Склад <id> принадлежит другой компании."]}` |
| Запрос не от владельца/админа | 403 |
